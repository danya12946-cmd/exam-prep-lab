# HTTP-контракт

**Базовое поведение**: серверные HTML-страницы на русском языке, `<html lang="ru">`. Все внутренние страницы требуют входа: неаутентифицированный запрос перенаправляется на `/accounts/login/?next=<path>`. Все POST-запросы требуют CSRF-токен. Ошибки форм возвращаются на той же странице с понятным русским сообщением.

**Доступ к попытке**: каждый view с `pk` попытки использует `get_object_or_404(Attempt, pk=pk, user=request.user)`. Чужая попытка — `404`, без имени темы, вопросов и результатов.

## Публичные и внутренние страницы

| Метод и путь | Назначение | Вход | Успех | Ошибки |
|---|---|---|---|---|
| `GET /accounts/signup/` | Форма регистрации | Нет | `200`, форма | — |
| `POST /accounts/signup/` | Создать аккаунт | Нет | `username`, `password1`, `password2`; пользователь создаётся и авторизуется; `302` на `/` | занятое имя, пустой/простой пароль, несовпадение паролей → `200` с ошибками формы |
| `GET /accounts/login/` | Форма входа | Нет | `200`, форма | — |
| `POST /accounts/login/` | Войти | Нет | `username`, `password`; `302` на `/` или `next` | неверные данные → `200` с ошибкой |
| `POST /accounts/logout/` | Выйти | Да | `302` на `/accounts/login/` | — |

## Основные сценарии

| Метод и путь | Назначение | Вход | Успех | Ошибки |
|---|---|---|---|---|
| `GET /` | Список тем | Да | `200`; для каждой темы название, описание, `question_count`; данные приходят из кэша `topics:list` | пустой список → сообщение «Темы пока не добавлены» |
| `POST /attempts/start/` | Начать тест | Да | `topic_id`; создаётся `Attempt` со снимками до 10 вопросов; `302` на `/attempts/<pk>/question/` | темы нет или вопросов 0 → `302` на `/` с сообщением; невалидный `topic_id` → то же |
| `GET /attempts/<pk>/question/` | Текущий вопрос | Да, владелец | `200`; текст вопроса, варианты из `options_snapshot`, индикатор «Вопрос N из M» | чужая/несуществующая попытка → `404`; нет неотвеченных → `302` на результат; попытка завершена → `302` на результат |
| `POST /attempts/<pk>/answer/` | Ответить на вопрос | Да, владелец | `option_key`; ответ сохраняется условным обновлением; если это последний вопрос — попытка завершается и будет `302` на `/attempts/<pk>/result/`, иначе `302` на следующий вопрос | чужой `pk` → `404`; ключ не из текущего снимка → `302` на вопрос с ошибкой; повторный ответ → `302` с сообщением «Ответ уже сохранён», старый ответ не меняется |
| `GET /attempts/<pk>/result/` | Результат и разбор | Да, владелец | `200`; «N из M», «P%», для каждого вопроса текст, ответ пользователя, правильный ответ и признак верности | чужая/несуществующая попытка → `404`; незавершённая → `302` на текущий вопрос |
| `GET /results/` | Мои результаты | Да | `200`; история завершённых попыток от новых к старым (дата, тема, результат) и лучший результат по каждой теме | нет попыток → понятные пустые состояния |
| `GET /topics/<topic_id>/leaderboard/` | Таблица лидеров темы | Да | `200`; до 10 строк: место, `username`, лучший процент; только завершённые попытки; данные из кэша | темы нет → `404`; результатов нет → сообщение «Результатов пока нет» |
| `GET /admin/` | Управление темами и вопросами | Да, `is_staff=True` | Django admin | не staff → отказ в доступе к административному интерфейсу |

## Инварианты ответов

- Повторный `POST /attempts/<pk>/answer/` не меняет `selected_option_key`, `is_correct`, счётчики и кэш.
- Завершённая попытка никогда не возвращается в `IN_PROGRESS`.
- Незавершённые попытки отсутствуют в `/results/`, лучших результатах и лидербордах.
- После изменений admin-контента или завершения попытки следующий запрос к затронутой странице возвращает актуальные данные без ручной очистки кэша.
