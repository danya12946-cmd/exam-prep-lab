# HTTP-контракт

**Базовое поведение**: серверные HTML-страницы на русском языке, `<html lang="ru">`. Все внутренние страницы требуют входа: неаутентифицированный запрос перенаправляется на `/accounts/login/?next=<path>`. Все POST-запросы требуют CSRF-токен. Ошибки форм возвращаются на той же странице с понятным русским сообщением. Тексты сообщений в таблицах ниже фиксированы и должны отображаться пользователю без изменений.

**Доступ к попытке**: каждый view с `pk` попытки использует `get_object_or_404(Attempt, pk=pk, user=request.user)`. Чужая попытка — `404`, без имени темы, вопросов и результатов.

## Публичные и внутренние страницы

| Метод и путь | Назначение | Вход | Успех | Ошибки |
|---|---|---|---|---|
| `GET /accounts/signup/` | Форма регистрации | Нет | `200`, форма | — |
| `POST /accounts/signup/` | Создать аккаунт | Нет | `username`, `password1`, `password2`; пользователь создаётся и авторизуется; `302` на `/` | занятое имя → «Имя пользователя уже занято»; пустой пароль → «Пароль не может быть пустым»; простой пароль → «Пароль слишком простой»; несовпадение паролей → «Пароли не совпадают» → `200` с ошибками формы |
| `GET /accounts/login/` | Форма входа | Нет | `200`, форма | — |
| `POST /accounts/login/` | Войти | Нет | `username`, `password`; `302` на `/` или `next` | неверные данные → `200` с сообщением «Неверное имя пользователя или пароль» |
| `POST /accounts/logout/` | Выйти (только POST) | Да | `302` на `/accounts/login/` | — |

## Основные сценарии

| Метод и путь | Назначение | Вход | Успех | Ошибки |
|---|---|---|---|---|
| `GET /` | Список тем | Да | `200`; для каждой темы название, описание, `question_count`; данные приходят из кэша `topics:list` | пустой список → сообщение «Темы пока не добавлены» |
| `POST /attempts/start/` | Начать тест | Да | `topic_id`; создаётся `Attempt` со снимками до 10 вопросов; `302` на `/attempts/<pk>/question/` | темы нет → «Тема не найдена»; вопросов 0 → «В теме нет вопросов»; невалидный `topic_id` → «Тема не найдена»; во всех случаях `302` на `/`, `Attempt` не создаётся |
| `GET /attempts/<pk>/question/` | Текущий вопрос | Да, владелец | `200`; текст вопроса, варианты из `options_snapshot`, индикатор «Вопрос N из M» | чужая/несуществующая попытка → `404`; нет неотвеченных → `302` на результат; попытка завершена → `302` на результат |
| `POST /attempts/<pk>/answer/` | Ответить на вопрос | Да, владелец | `option_key`; ответ сохраняется условным обновлением; если это последний вопрос — завершение попытки вызывается в том же запросе и будет `302` на `/attempts/<pk>/result/`, иначе `302` на следующий вопрос | чужой `pk` → `404`; отсутствующий или не из текущего снимка `option_key` → `302` на текущий вопрос с сообщением «Выберите один из предложенных вариантов», ответ не сохраняется; повторный ответ → `302` с сообщением «Ответ уже сохранён», старый ответ не меняется |
| `GET /attempts/<pk>/result/` | Результат и разбор | Да, владелец | `200`; «N из M», «P%», для каждого вопроса текст, ответ пользователя, правильный ответ и признак верности | чужая/несуществующая попытка → `404`; незавершённая → `302` на текущий вопрос |
| `GET /results/` | Мои результаты | Да | `200`; история завершённых попыток от новых к старым (дата, тема, «N из M», «P%») и лучший процент по каждой теме | нет попыток → понятные пустые состояния |
| `GET /topics/<topic_id>/leaderboard/` | Таблица лидеров темы | Да | `200`; до 10 строк: место, `username`, лучший процент; только завершённые попытки; данные из кэша; при равенстве процентов выше результат с `MIN(completed_at)` среди попыток с максимальным `percent` для пары `(user, topic_id_snapshot)`, при совпадении времени — по `username` по возрастанию | темы нет → `404`; результатов нет → сообщение «Результатов пока нет» |
| `GET /admin/` | Управление темами и вопросами | Да, `is_staff=True` | Django admin | не staff → отказ в доступе к административному интерфейсу |

Маршруты тем используют числовой `<topic_id>`; `Topic.slug` — стабильный ключ демо-данных, не часть URL.

## Инварианты ответов

- Повторный `POST /attempts/<pk>/answer/` не меняет `selected_option_key`, `is_correct`, счётчики и кэш.
- Невалидный `option_key` не создаёт ответ и не меняет счётчики и кэш.
- Завершение на последнем вопросе выполняется в том же POST-запросе, что и сохранение ответа; GET-страницы попытки статус не меняют.
- Завершённая попытка никогда не возвращается в `IN_PROGRESS`.
- Незавершённые попытки отсутствуют в `/results/`, лучших результатах и лидербордах.
- При работающем кэше после изменений admin-контента или завершения попытки следующий запрос к затронутой странице возвращает актуальные данные без ручной очистки кэша; после восстановления Valkey устаревшие значения заменяются актуальными не позднее чем через 5 минут (SC-007).
