# Quickstart: проверка приложения end-to-end

**Назначение**: краткая инструкция по запуску и проверке реализованного приложения. Детали API — в `contracts/http.md`, `contracts/cli.md`, `contracts/cache.md`; структура данных и инварианты — в `data-model.md`.

## Предварительные требования

- Docker и Docker Compose v2.
- Свободный порт `8001` на хосте (`8000` занят vibe-версией).
- Доступ к CDN Bootstrap 5 для корректного оформления (сама логика не зависит от CDN).

## Подготовка и запуск

```bash
cd sdd
cp .env.example .env
# отредактируйте .env: задайте случайные SECRET_KEY, POSTGRES_PASSWORD, VALKEY_PASSWORD
docker compose up --build -d
docker compose ps
```

`web` должен стартовать только после здоровых `db` и `valkey`. Entrypoint сам выполнит `collectstatic`, `migrate` и идемпотентную загрузку демо-данных; ручных действий до открытия сайта не требуется. Подробности — `contracts/cli.md`.

## Быстрая проверка инфраструктуры

```bash
docker compose exec db pg_isready -U exam -d exam
docker compose exec valkey valkey-cli ping
docker compose exec web python manage.py check --deploy
curl -I http://localhost:8001/
```

Ожидаемо: `pg_isready` принимает подключения; Valkey отвечает `PONG`; `check --deploy` не показывает критичных ошибок; главная страница для невошедшего пользователя отдаёт redirect на вход.

## Автотесты

```bash
docker compose exec web python manage.py test
```

Ожидаемо: все тесты проходят. Отдельно проверяются кэш `LocMemCache`, отсутствие SQL при повторном чтении, инвалидация после изменений, ограничения базы, запрет повторного ответа и недоступность чужих попыток.

## Сценарии ручной проверки

| Сценарий | Действия | Ожидаемый результат |
|---|---|---|
| Регистрация и вход | Зарегистрировать пользователя, выйти, войти снова; открыть внутреннюю страницу без входа | Вход/выход работают; без входа — redirect на логин. См. `contracts/http.md` |
| Список тем | Открыть `/` после входа | 3 демо-темы, у каждой описание и количество вопросов 12 |
| Прохождение теста | Начать тест по теме с 12 вопросами; пройти до конца | 10 случайных вопросов, индикатор «Вопрос 1 из 10» … «Вопрос 10 из 10», вопросы по одному |
| Запрет повторного ответа | Обновить страницу после ответа или отправить тот же POST повторно | Ответ не меняется, сообщение об уже сохранённом ответе |
| Результат и разбор | Ответить, например, на 7 из 10 вопросов верно | Показаны «7 из 10», «70%» и разбор всех 10 вопросов с исходными формулировками |
| Мои результаты | Пройти 2–3 попытки, открыть `/results/` | История от новых к старым, лучшие результаты по темам, переход в разбор |
| Чужая попытка | Открыть ссылку на разбор другого пользователя | `404`, содержимое не раскрывается |
| Лидерборд | Открыть таблицу лидеров темы; создать пустую тему | До 10 пользователей, сортировка по убыванию процента; для пустой темы — сообщение об отсутствии результатов |
| Целостность истории | После завершённой попытки изменить/удалить вопрос администратором, затем открыть старый разбор и новый тест | Старый разбор неизменён; новый тест использует обновлённый контент |
| Актуальность кэша | Повторить чтение списка тем/лидерборда/лучших результатов; изменить данные через admin или завершить попытку | Повторное чтение не делает SQL (проверяется тестами), после изменения данные сразу свежие. См. `contracts/cache.md` |
| Демо-данные | Запустить `python manage.py load_demo_data` ещё раз | Количество тем и вопросов не увеличивается, правки администратора не перезаписаны |

## Проверка ограничений базы

```bash
docker compose exec web python manage.py test exams.tests.test_admin_integrity
```

Проверяемые правила: вопрос с 1 или 7 вариантами не сохраняется; вопрос без правильного или с двумя правильными вариантами не сохраняется; завершённая попытка не искажается после правок контента. Детали ограничений — `data-model.md`.

## Ожидаемые артефакты после запуска

- Сайт доступен на `http://localhost:8001/`.
- В Django admin доступны темы и вопросы; обычный пользователь не попадает в admin.
- Демо-данные присутствуют сразу и не дублируются при повторном старте.
- Все тесты проходят, логи web не содержат ошибок подключения к `db` или `valkey`.
