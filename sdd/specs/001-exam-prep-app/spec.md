# Feature Specification: Веб-приложение для подготовки к экзамену

**Feature Branch**: `001-exam-prep-app`

**Created**: 2026-11-23

**Status**: Draft

**Input**: User description: "Веб-приложение для подготовки к экзамену. Пользователи регистрируются и входят в систему. После входа пользователь видит список тем с описанием и количеством вопросов в каждой. Пользователь выбирает тему и проходит тест из 10 случайных вопросов этой темы (если вопросов меньше 10 — из всех). Вопросы показываются по одному, с индикатором прогресса («Вопрос 3 из 10»). Повторно ответить на уже отвеченный вопрос нельзя. После теста пользователь видит результат: количество и процент правильных ответов и разбор каждого вопроса — его ответ и правильный ответ. На странице «Мои результаты» — история попыток (дата, тема, результат) и лучший результат по каждой теме. Для каждой темы есть таблица лидеров: топ-10 пользователей по лучшему проценту правильных ответов. Администратор управляет темами и вопросами. У каждого вопроса от 2 до 6 вариантов ответа и ровно один правильный. Если администратор меняет вопросы, история уже пройденных попыток не должна искажаться. Пользователь видит только свои попытки; чужие попытки недоступны даже по прямой ссылке. Для быстрого старта есть демо-данные: 3 темы по 12 вопросов."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Прохождение теста по теме и разбор результата (Priority: P1)

Вошедший пользователь выбирает тему из списка и проходит тест: система случайно отбирает 10 вопросов темы (если вопросов меньше 10 — берутся все). Вопросы показываются по одному, с индикатором прогресса («Вопрос 3 из 10»). Пользователь выбирает один вариант ответа и переходит к следующему вопросу; вернуться и переответить на уже отвеченный вопрос нельзя. После последнего вопроса пользователь видит результат: количество и процент правильных ответов, а также разбор каждого вопроса — свой ответ и правильный ответ.

**Why this priority**: Это основная ценность продукта — самопроверка знаний. Без прохождения теста и разбора результата приложение не выполняет своё назначение.

**Independent Test**: С существующей учётной записью и демо-данными пройти тест по теме от начала до конца и проверить: состав из 10 случайных вопросов, показ по одному, индикатор прогресса, запрет повторного ответа, корректность итогового количества, процента и разбора.

**Acceptance Scenarios**:

1. **Given** в теме 12 вопросов и пользователь вошёл в систему, **When** он начинает тест по этой теме, **Then** тест содержит ровно 10 случайно выбранных вопросов, первый вопрос показан с индикатором «Вопрос 1 из 10».
2. **Given** в теме 6 вопросов, **When** пользователь начинает тест, **Then** тест содержит все 6 вопросов, индикатор показывает «Вопрос 1 из 6».
3. **Given** пользователь ответил на 3-й вопрос из 10, **When** отображается следующий вопрос, **Then** индикатор показывает «Вопрос 4 из 10», а вернуться к 3-му вопросу и изменить ответ невозможно.
4. **Given** пользователь пытается повторно отправить ответ на уже отвеченный вопрос (в том числе прямой отправкой запроса), **When** система обрабатывает запрос, **Then** повторный ответ отклоняется, ранее данный ответ сохраняется без изменений.
5. **Given** пользователь ответил на все вопросы теста, **When** тест завершается, **Then** показаны количество правильных ответов, процент правильных и разбор каждого вопроса: текст вопроса, ответ пользователя и правильный ответ.
6. **Given** пользователь ответил правильно на 7 из 10 вопросов, **When** он смотрит результат, **Then** отображается «7 из 10» и «70%», и в разборе ровно 7 вопросов отмечены как отвеченные верно.

### User Story 2 - Регистрация, вход и список тем (Priority: P2)

Новый пользователь регистрируется, указав имя пользователя и пароль, затем входит в систему. После входа он видит список тем: название, описание и количество вопросов в каждой теме. Из списка тем можно перейти к прохождению теста. Невошедший пользователь не видит содержимое приложения и перенаправляется к входу.

**Why this priority**: Регистрация и вход — обязательный фундамент: без учётной записи невозможны персональные попытки, история и таблицы лидеров. Список тем — точка входа в основной сценарий.

**Independent Test**: Зарегистрировать нового пользователя, войти, убедиться, что виден список из 3 демо-тем с описаниями и количеством вопросов (по 12), и что без входа страницы приложения недоступны.

**Acceptance Scenarios**:

1. **Given** посетитель не зарегистрирован, **When** он заполняет форму регистрации корректными данными, **Then** создаётся учётная запись и он получает доступ к приложению.
2. **Given** имя пользователя уже занято, **When** посетитель пытается зарегистрироваться с тем же именем, **Then** регистрация отклоняется с понятным сообщением.
3. **Given** пользователь вошёл в систему и загружены демо-данные, **When** он открывает главную страницу, **Then** видит 3 темы, у каждой — название, описание и количество вопросов (12).
4. **Given** посетитель не вошёл в систему, **When** он открывает любую внутреннюю страницу приложения по прямой ссылке, **Then** он перенаправляется на страницу входа.
5. **Given** пользователь вошёл в систему, **When** он выходит из неё, **Then** внутренние страницы снова становятся недоступны без повторного входа.

### User Story 3 - Мои результаты: история попыток и лучшие результаты (Priority: P3)

На странице «Мои результаты» пользователь видит историю своих завершённых попыток: дата, тема, результат (количество и процент правильных). Также показан лучший результат по каждой теме, по которой есть завершённые попытки. Из истории можно открыть разбор конкретной попытки. Чужие попытки недоступны: при обращении по прямой ссылке к чужой попытке пользователь получает отказ в доступе.

**Why this priority**: Отслеживание прогресса — ключевая мотивация повторного использования приложения; история и лучшие результаты показывают динамику подготовки.

**Independent Test**: Пройти несколько тестов по разным темам, открыть «Мои результаты» и проверить полноту истории, корректность лучших результатов по темам и недоступность попытки другого пользователя по прямой ссылке.

**Acceptance Scenarios**:

1. **Given** пользователь завершил 3 попытки по двум темам, **When** он открывает «Мои результаты», **Then** видит 3 записи истории с датой, темой и результатом, отсортированные от новых к старым.
2. **Given** по теме «Алгебра» есть попытки с результатами 60% и 90%, **When** пользователь смотрит лучшие результаты, **Then** по этой теме показан лучший результат 90%.
3. **Given** пользователь A знает прямую ссылку на разбор попытки пользователя B, **When** A открывает эту ссылку, **Then** доступ запрещается, содержимое чужой попытки не раскрывается.
4. **Given** пользователь кликает по записи своей истории, **When** открывается разбор попытки, **Then** он видит вопросы, свои ответы и правильные ответы такими, какими они были на момент прохождения.

### User Story 4 - Таблица лидеров по теме (Priority: P4)

Для каждой темы доступна таблица лидеров: топ-10 пользователей по лучшему проценту правильных ответов по этой теме. В таблице видны место, имя пользователя и его лучший процент. Таблица отражает только завершённые попытки и обновляется после появления новых лучших результатов.

**Why this priority**: Соревновательный элемент повышает вовлечённость, но не обязателен для базовой подготовки к экзамену.

**Independent Test**: Несколько пользователей проходят тесты по одной теме с разными результатами; проверить, что таблица лидеров темы содержит до 10 пользователей, отсортированных по лучшему проценту по убыванию, и каждый пользователь представлен один раз.

**Acceptance Scenarios**:

1. **Given** 12 пользователей завершили попытки по теме с разными лучшими процентами, **When** открывается таблица лидеров темы, **Then** показаны ровно 10 пользователей с наибольшими лучшими процентами, по убыванию.
2. **Given** у пользователя две попытки по теме — 50% и 80%, **When** формируется таблица лидеров, **Then** пользователь учитывается один раз с результатом 80%.
3. **Given** по теме ещё никто не завершил тест, **When** открывается таблица лидеров, **Then** показывается понятное сообщение об отсутствии результатов, а не ошибка.

---

### User Story 5 - Управление контентом администратором с сохранением истории (Priority: P5)

Администратор создаёт и редактирует темы и вопросы. У каждого вопроса от 2 до 6 вариантов ответа, ровно один из них правильный; сохранить вопрос, нарушающий эти правила, нельзя. Изменение или удаление вопросов и вариантов ответа не искажает историю уже завершённых попыток: в разборе старой попытки остаются исходные формулировки вопросов, вариантов и правильных ответов.

**Why this priority**: Контент необходимо поддерживать, но для первого запуска достаточно демо-данных; целостность истории — критичное ограничение этой истории.

**Independent Test**: Завершить попытку, затем как администратор изменить текст вопроса и правильный ответ, удалить другой вопрос из темы; открыть разбор старой попытки и убедиться, что он не изменился, а новый тест использует обновлённый контент.

**Acceptance Scenarios**:

1. **Given** администратор вошёл в систему, **When** он создаёт тему и вопрос с 4 вариантами ответа и одним правильным, **Then** тема и вопрос сохраняются и доступны пользователям.
2. **Given** администратор редактирует вопрос, **When** он пытается сохранить вопрос с 1 вариантом ответа, с 7 вариантами или без правильного ответа / с двумя правильными, **Then** сохранение отклоняется с понятным сообщением.
3. **Given** пользователь завершил попытку, **When** администратор меняет текст вопроса, который был в этой попытке, и его правильный ответ, **Then** разбор завершённой попытки показывает прежние формулировки и прежний правильный ответ, результат попытки не меняется.
4. **Given** пользователь завершил попытку, **When** администратор удаляет вопрос, входивший в попытку, **Then** разбор попытки по-прежнему содержит этот вопрос и ответ пользователя.

---

### Edge Cases

- В теме 0 вопросов: тест начать нельзя, пользователь видит понятное сообщение вместо пустого теста.
- В теме ровно 10 вопросов: тест содержит все 10; порядок вопросов случаен.
- Выборка вопросов случайна: две попытки по одной теме могут отличаться составом и порядком вопросов.
- Пользователь прервал тест (закрыл вкладку, вышел из системы): незавершённая попытка не попадает в историю завершённых попыток, лучшие результаты и таблицу лидеров; пользователь может начать новую попытку по теме.
- Повторная отправка ответа на уже отвеченный вопрос (кнопкой «назад», обновлением страницы или прямым запросом) не меняет сохранённый ответ.
- Обращение к чужой попытке или чужому разбору по прямой ссылке — отказ в доступе без раскрытия содержимого.
- Администратор удаляет тему целиком: завершённые попытки по ней остаются в истории пользователей с исходными данными.
- Одинаковые лучшие проценты у нескольких пользователей в таблице лидеров: порядок детерминирован (ранее достигнутый результат выше; при совпадении времени — по имени пользователя).
- Процент правильных ответов округляется до целого числа (например, 2 из 3 → 67%).
- Регистрация с пустым паролем или слишком простым паролем отклоняется стандартными правилами безопасности.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST позволять посетителю зарегистрироваться по имени пользователя и паролю; имя пользователя MUST быть уникальным.
- **FR-002**: Система MUST позволять зарегистрированному пользователю входить в систему и выходить из неё; все внутренние страницы MUST быть доступны только вошедшим пользователям.
- **FR-003**: После входа система MUST показывать список тем с названием, описанием и количеством вопросов в каждой теме.
- **FR-004**: Система MUST позволять начать тест по выбранной теме; тест MUST содержать 10 случайно выбранных вопросов темы, а если вопросов меньше 10 — все вопросы темы.
- **FR-005**: Система MUST показывать вопросы теста по одному, с индикатором прогресса вида «Вопрос N из M».
- **FR-006**: Система MUST принимать ровно один ответ на каждый вопрос попытки; повторный ответ на уже отвеченный вопрос MUST отклоняться на серверной стороне, ранее сохранённый ответ MUST оставаться неизменным.
- **FR-007**: После ответа на последний вопрос система MUST завершать попытку и показывать результат: количество правильных ответов, процент правильных (округлённый до целого) и разбор каждого вопроса — текст вопроса, ответ пользователя и правильный ответ.
- **FR-008**: Система MUST предоставлять страницу «Мои результаты» со списком завершённых попыток текущего пользователя (дата, тема, количество и процент правильных), отсортированным от новых к старым, и лучшим результатом по каждой теме.
- **FR-009**: Система MUST предоставлять для каждой темы таблицу лидеров: до 10 пользователей с наибольшим личным лучшим процентом по теме, по убыванию; каждый пользователь MUST присутствовать в таблице не более одного раза; в зачёт MUST идти только завершённые попытки.
- **FR-010**: Система MUST позволять пользователю открыть разбор любой своей завершённой попытки из истории.
- **FR-011**: Система MUST проверять право доступа к попытке на серверной стороне при каждом запросе: пользователь MUST видеть только свои попытки; обращение к чужой попытке, в том числе по прямой ссылке, MUST отклоняться без раскрытия её содержимого.
- **FR-012**: Система MUST предоставлять администратору возможность создавать, редактировать и удалять темы и вопросы.
- **FR-013**: Система MUST гарантировать, что каждый вопрос имеет от 2 до 6 вариантов ответа и ровно один правильный вариант; сохранение вопроса, нарушающего эти правила, MUST быть невозможно.
- **FR-014**: Разбор и результат завершённой попытки MUST сохранять данные на момент прохождения (формулировки вопросов и вариантов, правильный ответ, ответ пользователя); изменение или удаление вопросов, вариантов и тем администратором MUST NOT искажать завершённые попытки.
- **FR-015**: Система MUST запрещать начинать тест по теме без вопросов и показывать понятное сообщение.
- **FR-016**: Незавершённые попытки MUST NOT учитываться в истории завершённых попыток, лучших результатах и таблицах лидеров; пользователь MUST иметь возможность начать новую попытку по теме.
- **FR-017**: Система MUST поставляться с демо-данными: 3 темы по 12 вопросов с вариантами ответа и отмеченными правильными ответами, доступными сразу после развёртывания.
- **FR-018**: Пользовательский интерфейс и сообщения системы MUST быть на русском языке.
- **FR-019**: Система MUST сразу отражать актуальные данные: после создания, изменения или удаления вопросов администратором количество вопросов в списке тем MUST обновляться сразу; после завершения попытки «Мои результаты» и таблица лидеров MUST обновляться сразу.

### Key Entities

- **Пользователь**: учётная запись с уникальным именем и паролем; владеет своими попытками; может иметь роль администратора.
- **Тема**: раздел вопросов с названием и описанием; количество вопросов вычисляется из состава темы.
- **Вопрос**: текст вопроса, принадлежность теме, от 2 до 6 вариантов ответа, ровно один правильный вариант.
- **Вариант ответа**: текст варианта, принадлежность вопросу, признак правильности.
- **Попытка**: прохождение теста пользователем по теме; дата начала/завершения, статус (в процессе / завершена), итоговые количество и процент правильных; содержит снимок данных на момент прохождения.
- **Ответ в попытке**: зафиксированный вопрос (снимок формулировки и вариантов), выбранный пользователем вариант, правильный вариант на момент прохождения, признак верности ответа.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Новый пользователь проходит путь от регистрации до первого результата теста менее чем за 5 минут без посторонней помощи.
- **SC-002**: 100% завершённых попыток показывают результат и разбор, полностью соответствующие данным вопросам и ответам пользователя (проверяется сверкой на контрольных прохождениях).
- **SC-003**: 0 случаев доступа к чужой попытке при проверке прямыми ссылками от имени другого пользователя.
- **SC-004**: 100% завершённых попыток сохраняют исходный разбор и результат после любых изменений контента администратором (проверяется контрольным сценарием «пройти → изменить → сверить»).
- **SC-005**: Повторное открытие списка тем, таблицы лидеров и лучших результатов не выполняет запросов к базе данных, пока данные не изменились; после изменения данных пользователь сразу видит актуальные значения (проверяется подсчётом запросов и контрольным сценарием «изменить данные → открыть страницу»).
- **SC-006**: Демо-данные (3 темы по 12 вопросов) доступны сразу после развёртывания без ручных действий.

## Assumptions

- Аутентификация — стандартная, по имени пользователя и паролю, с сессией входа; восстановление пароля по электронной почте и внешние провайдеры входа в объём первой версии не входят.
- Администратор управляет контентом через встроенную административную панель; отдельный пользовательский интерфейс управления контентом не требуется.
- Прерванная попытка остаётся незавершённой и исключается из истории, лучших результатов и лидеров; продолжение прерванной попытки с того же места в первой версии не поддерживается — пользователь начинает новую попытку.
- Ограничения времени на вопрос или на весь тест отсутствуют.
- Процент правильных округляется до целого числа по математическим правилам.
- При равенстве лучших процентов в таблице лидеров выше располагается результат, достигнутый раньше; при полном совпадении — сортировка по имени пользователя.
- Таблицы лидеров видны всем вошедшим пользователям и содержат только имя пользователя и лучший процент (без деталей чужих попыток).
- Целевая аудитория — учащиеся, готовящиеся к экзамену; интерфейс русскоязычный, нагрузка учебная (десятки одновременных пользователей).
- Демо-данные загружаются автоматически при развёртывании и не перезаписывают пользовательские данные при повторном развёртывании.
