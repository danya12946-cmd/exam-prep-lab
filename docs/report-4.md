# Отчёт: оценка «4» — вайбкодинг веб-приложения

## Задача
Веб-приложение для подготовки к экзамену на Django + PostgreSQL, запуск в Docker Compose.
Код писал агент opencode (модели DeepSeek V4.1 Flash Free → Big Pickle), я ставил задачи и делал ревью.

## Процесс
Подробный журнал: [vibe-log.md](vibe-log.md)

1. **Промпт 1** — общее описание приложения (функции + техтребования).
   Агент упёрся в дневной лимит бесплатной модели, переключился на Big Pickle и продолжил.
   Результат: рабочее приложение, 17 тестов, демо-данные (3 темы × 12 вопросов).
2. **Ревью кода** — проверил настройки, модели, compose, безопасность.
3. **Промпт 2** — исправление замечаний ревью. Результат: 19 тестов.

Всего: [N] промптов, примерно [N] минут.

## Код-ревью

| № | Замечание | Как найдено | Исправлено |
|---|---|---|---|
| 1 | `DEBUG=True` по умолчанию — при ошибке видно устройство сайта | чтение settings.py + страница 404 | ✅ default=False |
| 2 | Можно создать вопрос без правильного ответа | чтение models.py | ✅ валидация в админке + тест |
| 3 | Нет `.dockerignore` — `.env` с паролями копировался в образ | `ls -a`, лог сборки | ✅ |
| 4 | `runserver` (сервер для разработки) вместо `gunicorn` | чтение compose.yaml | ✅ gunicorn + whitenoise |
| 5 | Доступ к чужим попыткам по прямой ссылке | ручной тест вторым пользователем | ✅ уже было защищено (404) |

## Выводы
- Вайбкодинг дал рабочий результат очень быстро, почти с первого промпта.
- Но без ревью в проекте остались бы небезопасные настройки по умолчанию: агент делает «чтобы работало»,
  а не «чтобы было безопасно», если явно не попросить.
- Требования формулировались на ходу, часть из них появилась только после ревью.
  Это сравним с SDD-подходом на «5».
