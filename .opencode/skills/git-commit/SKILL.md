# Skill: аккуратный коммит

## Шаги
1. Выполни `git status` и `git diff`, чтобы понять, что изменилось.
2. Проверь, что в изменения не попали секреты и мусор: `.env`, пароли, ключи,
   `__pycache__/`, `.venv/`, `db.sqlite3`. Если попали — остановись и сообщи мне.
3. Если изменения относятся к разным задачам — раздели их на несколько коммитов.
4. Добавляй файлы явно: `git add <файл1> <файл2>`, а не `git add .` вслепую.
5. Сообщение коммита — по формату `<тип>(<область>): <что сделано>`:
   - типы: `feat` (новая функция), `fix` (исправление), `docs` (документация),
     `refactor`, `test`, `chore` (настройки, зависимости), `style`;
   - первая строка не длиннее 72 символов, на русском, с маленькой буквы, без точки;
   - при необходимости после пустой строки — пояснение, что и зачем.
6. После коммита покажи `git log --oneline -5`.
7. Не делай `git push`, если пользователь об этом явно не попросил.

## Примеры хороших сообщений
- `feat(quiz): добавить страницу прохождения теста`
- `fix(auth): исправить редирект после входа`
- `docs: описать запуск через docker compose в README`
- `chore(opencode): подключить MCP-сервер context7`
